# 0. О чём этот курс

Алгебры фон Неймана изучают почти исключительно с бумагой и карандашом. В конечной размерности
каждая из них есть прямая сумма полных матричных алгебр (глава 2), так что в принципе всё можно
вычислить, но на практике алгебру обычно разворачивают в одну большую матрицу, и её структура
(секторы, центр, множество следов) исчезает из вычисления. Этот курс и библиотека
`torch_vn_algebra` поступают наоборот: **сама алгебра является типом данных**, и вычисления в ней
выполняются эффективно.

## 0.1 Основное наблюдение

Конечномерная алгебра фон Неймана с точностью до унитарной замены базиса имеет вид
$$
\mathcal M=\bigoplus_{c=1}^CM_{k_c}(\mathbb C)\otimes1_{m_c}
$$
(теорема 2.6). Как абстрактная алгебра она есть $\bigoplus_cM_{k_c}(\mathbb C)$: элемент — это список
из $C$ квадратных блоков. Это в точности форма тензора с *осью секторов*: элемент $\mathcal M$ —
массив формы $(C,k,k)$ (блоки дополняются до размера $k=\max_ck_c$), а $B$ элементов — выборки
Монте-Карло, начальные точки оптимизации, шаги по времени, реализации беспорядка — образуют массив
формы $(B,C,k,k)$. Современные библиотеки для работы с массивами (PyTorch на CPU и GPU) созданы
именно для таких «пакетов малых матриц», потому что они нужны нейронным сетям.

При таком отождествлении операции алгебры становятся пакетными операциями над массивами, причём
точно и без всякого приближения:

| в алгебре $\mathcal M$ | над массивом формы $(B,C,k,k)$ |
|---|---|
| произведение $AB$, сумма, сопряжение | пакетное матричное произведение, сумма, эрмитово сопряжение по $(B,C)$ |
| функциональное исчисление $f(A)$ (глава 1) | пакетное спектральное разложение блоков |
| след $\sum_cw_c\operatorname{Tr}A_c$ (глава 3) | сумма диагонали в каждом блоке, взвешенная сумма по оси секторов |
| центр, центральные проекторы (глава 2) | одно число на сектор |
| условное ожидание на центр | след блока, делённый на $k_c$ и размноженный обратно |
| мера Хаара на унитарной группе $\prod_cU(k_c)$ | пакетное QR-разложение гауссовых блоков (глава 5) |
| состояния, каналы, динамика (главы 3, 6, 8) | те же операции в композиции |

Два следствия делают это чем-то большим, чем просто учёт.

- **Стоимость.** Спектральное разложение в $\mathcal M$ стоит $\sum_ck_c^3$ операций (блоки
  группируются по размеру) против $D^3$ для вложения в $M_D(\mathbb C)$, $D=\sum_ck_c$; для $C$
  одинаковых блоков выигрыш составляет $C^2$ раз. Произведения и суммы выполняются на дополненном
  нулями тензоре и стоят $C\,k_{\max}^3$, что совпадает с $\sum_ck_c^3$, когда все блоки одного
  размера. Произведения, суммы и следы обрабатывают все $B\cdot C$ блоков одним вызовом;
  разложения (собственные и сингулярные значения) выполняются одним пакетным вызовом на каждый
  различный размер блока — одним-единственным вызовом, если все секторы одного размера, — а на
  многоядерном CPU библиотека разбивает каждый такой вызов на части, по одной на поток. Это
  полностью загружает GPU или все ядра CPU.
- **Корректность по построению.** Всё вычисляемое остаётся в $\mathcal M$: случайные унитарные
  элементы распределены по Хаару на $\prod_cU(k_c)$ (это множество меры нуль в $U(D)$, которое
  никогда не получится при выборке из $U(D)$), шаги градиентного спуска не выводят из алгебры,
  а след, плотности и условные ожидания относятся к самой алгебре, а не к случайно выбранному вложению.

## 0.2 Первое вычисление

Сравним одно и то же вычисление в $\mathcal M=\bigoplus_{c=1}^{64}M_{16}(\mathbb C)$ и в её вложении
в $M_{1024}(\mathbb C)$: квадратный корень из случайного положительного элемента и его след.
`TypeIAlgebra(n_factors, k_factors)` принимает два списка размеров блоков: номинальные размеры
$n_c$ и размеры $k_c\le n_c$ реально используемых блоков; в этом курсе оба списка всегда
совпадают (раздел 1.5).

```python
import time
import torch
from torch_vn_algebra import TypeIAlgebra

torch.manual_seed(0)
C, k = 64, 16
alg = TypeIAlgebra([k] * C, [k] * C, precision='double')       # M = (+)_{c=1}^{64} M_16(C)

A = alg.operator_from_eigenvalues(lambda d: 0.1 + torch.rand(1, d), force_positive=True)

t0 = time.perf_counter()
root_blocks = A.sqrt().matrix                                    # (1, 64, 16, 16): 64 small eigenproblems
t_blocks = time.perf_counter() - t0

big = torch.block_diag(*A.matrix[0])                             # the same element in M_1024(C)
t0 = time.perf_counter()
w, V = torch.linalg.eigh(big)                                    # one large eigenproblem
root_big = (V * w.sqrt()) @ V.conj().T
t_big = time.perf_counter() - t0

assert torch.allclose(torch.block_diag(*root_blocks[0]), root_big, atol=1e-10)   # same result
assert abs(A.sqrt().Tr_blunt().item() - root_big.trace().item()) < 1e-9
print(f"in the algebra: {t_blocks * 1e3:.1f} ms, as one 1024 x 1024 matrix: {t_big * 1e3:.1f} ms")
```

Результаты совпадают с точностью до ошибок округления. Вариант в алгебре на CPU быстрее в десятки
раз (около 10 мс против 400 мс на 4-ядерной машине; точные числа зависят от оборудования — код
их печатает). Все 64 блока передаются спектральному решателю одним пакетным вызовом, который на
многоядерном CPU библиотека разбивает на части, по одной на поток. Ускорение всё же гораздо
меньше, чем можно было бы ожидать по отношению числа операций $C^2=4096$, поскольку один вызов
большой спектральной задачи использует оборудование лучше, чем много малых. Разрыв растёт с
числом секторов, а экономия памяти составляет $C$ раз. Для пакета из $B$ элементов вариант в
алгебре по-прежнему требует одного пакетного вызова, а вариант с большой матрицей превращается
в $B$ больших спектральных задач.

## 0.3 Что уже есть и что нового

Мы искали программы, которые выполняют численные вычисления *внутри* конечномерных алгебр фон
Неймана. Найденное распадается на четыре группы — все полезные и все с разными целями:

- **Универсальные матричные программы** (NumPy/SciPy, QuTiP и другие квантовые пакеты) работают
  с одной матрицей за раз. Блочную структуру, если она есть, приходится поддерживать вручную.
- **Библиотеки симметричных тензорных сетей** хранят тензоры как блочно-разреженные массивы по
  зарядовым секторам абелевой симметрии, причём некоторые имеют бэкенд на PyTorch для GPU и
  автоматического дифференцирования (например, YASTN [1]; а также TeNPy, ITensor, TensorKit).
  Технически это ближайшие родственники. Их объект — тензорная сеть, которую нужно свернуть, а не
  операторная алгебра: в них нет семейства следов, состояний и плотностей, центра и условных
  ожиданий, мер Хаара на $\prod_cU(k_c)$ и каналов между секторами.
- **Численная блочная диагонализация** матричных $*$-алгебр [2, 3, 4] находит разложение
  $\mathcal M\cong\bigoplus_cM_{k_c}\otimes1_{m_c}$ заданной алгебры — как правило, чтобы уменьшить
  размер полуопределённых программ с симметрией. Это дополняет наш подход: те алгоритмы находят
  блоки, а эта библиотека в них вычисляет и реализует один из них как входной шаг (`decompose`,
  глава 4). Точные символьные разложения групповых алгебр есть в
  системах компьютерной алгебры (например, пакет GAP Wedderga).
- **Некоммутативная полиномиальная оптимизация** (NCSOStools, ncpol2sdpa) с помощью
  полуопределённых релаксаций [5] даёт оценки собственных значений и следов многочленов от
  некоммутирующих переменных сразу для всех размеров матриц. Она отвечает на другой вопрос (оценка,
  верная для всех алгебр) другими средствами (выпуклая релаксация).

Насколько нам известно, не существует универсальной библиотеки, в которой конечномерная алгебра
фон Неймана была бы базовым типом данных для пакетных дифференцируемых численных вычислений.
Поэтому новизна состоит не в новой математике, а в **эффективных вычислениях**: отождествление
из §0.1 реализовано так, что структура алгебры сохраняется, а каждая операция выполняется
пакетными ядрами (для разложений — по одному на каждый различный размер блока, с разбиением на части
по потокам на многоядерном CPU). Если вы знаете о родственных программах, мы будем рады узнать о них.

## 0.4 Как читать этот курс

| главы | содержание |
|---|---|
| 1–3 | математика: матричные алгебры, структурная теорема, следы, состояния и энтропия — с полными доказательствами |
| 4–8 | откуда берутся эти алгебры и что в них вычисляют: симметрии, случайные матрицы, каналы, тензорные произведения, динамика |
| 9–12 | приложения: спиновые цепочки, квантовые вычисления, оптимизация, эквивариантное машинное обучение |

В каждой главе результаты формулируются и доказываются, приводится код библиотеки, код проверяется
по точному результату и называются стандартные инструменты для сравнения.
